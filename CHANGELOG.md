# Changelog

All notable changes to this workshop are recorded here.

## Unreleased

### Added

- The 13 figures that Modules 9 to 15 had specified only in comments: the text-as-MDP strip, measured baseline variance and the reward model (9); the RLHF pipeline and a schematic of reward over-optimization (10); measured reliability diagrams and a risk-coverage curve (11); the act/ask/escalate costs and a decision model as router, guard and verifier (12); the RAG pipeline and bi- versus cross-encoder (13); the desk agent's graph (14); and the capstone's graph (15). They are drawn by `scripts/make_figures_09_11.py` and `scripts/make_figures_12_15.py`. Module 11's plots are recomputed with Lab 11's code into `images/11-calibration.json`, matching the recorded summary numbers. The system diagrams follow the lab code where it differs from the original spec, and tag the exercise that writes each part.
- `tests/test_style.py`: published prose and the generators that write it use American spelling, and every title and heading uses title case. Code, URLs and cited titles are skipped.
- A [glossary and notation index](glossary.qmd) (50 terms, 34 symbols, each with where it is defined and the exercise that implements it) and a [results worksheet](worksheet.qmd) with a CSV download (18 comparison groups, each saying what makes its rows comparable). Both are generated from data files (`_glossary.yml`, `_worksheet.yml`) by `scripts/learner_pages.py` and checked by `tests/test_learner_pages.py`. Each module links the terms it introduces.
- Under each agenda, a **Read Now / Use in the Lab / Read Later** guide, and in each lab table a "Briefing section" column, from a new `lab:` front-matter map of which sections each exercise uses.
- Comparison tables at five module transitions (cross- versus self-attention; pretraining, full fine-tuning and LoRA; reward-model fitting, policy optimization and DPO; accuracy, calibration and decision cost; the retrieval pipeline and the agent loop), and one transfer question per module (T1–T15).
- Folded hints in every lab (47), and checkpoint messages that show observed against expected and name the likely mistake (255 rewritten). A failed checkpoint points at the hint; the last cell of every notebook says which path ran (offline stand-ins, real open models or commercial APIs) and, without keys, what the module's fallback means.
- A pilot protocol and observation form (`pilot/`), prepared, not run.
- Intro slides (`welcome.qmd`, a Quarto revealjs deck with its own theme, `slides.scss`): the ten-minute opening of Day 1, the setup check and the week ahead. Its five-days and timetable slides are generated from `_variables.yml` (`_includes/welcome-days.md`, `_includes/welcome-clocks.md`), and the schedule's "Welcome, setup check" slot links to it (`days.d1.opening_page`). Linked from the landing page, Before Day 1, the schedule, Day 1, the teach page, the facilitator guide, the pace sheet and the README. `scripts/check_browser.py` checks a deck for errors and slides instead of for the site's navbar.
- Exercise harness: every notebook gets a generated harness cell and a summary cell. A folded solution now stores the reference and binds it only in worked mode (`WORKED_EXAMPLE`, or `NLP_LLMS_WORKED=1` in CI). Every checkpoint says whether it checked the participant's code or the reference. A stuck participant can call `workshop.use_reference(N)`. The last cell prints which checkpoints passed on whose code, and a run record. `scripts/test_notebooks.py` gains `--learner`, `--verify-checkpoints` and `--record`; `scripts/add_run_record.py` and `tests/test_exercises.py` are new.
- Readiness from evidence: a `readiness` block and per-module readiness fields in `_variables.yml`, run records in `runs/` (schema, validator, records backfilled from CI and the briefs), `scripts/readiness.py`, and a generated [readiness page](readiness.qmd) with a one-paragraph status on the landing, FAQ, teach and facilitator pages and in the README. The status says plainly that no lab has yet run on Colab.

- Master plan (`PLAN.md`) for a four-day, 15-module workshop, and agent guidance with four build personas (`AGENTS.md`).
- Quarto website scaffold: landing, setup, schedule, four day pages, 15 lecture stubs, notebooks index, references, teach and FAQ pages.
- `_variables.yml` as the single source of truth, with generators for the schedule, module and notebook tables and for notebook header and footer cells.
- Notebook template, `00-setup.ipynb`, a notebook runner and an internal link check.
- CI workflow: generate, drift gate, lint, test, render, link check, notebook execution, and opt-in deployment to GitHub Pages.
- Scheduled notebook health workflow (`health.yml`): a weekly hermetic run, a non-blocking run of the open-model (Hub) paths, and an on-demand run with API keys. The pull-request notebook run no longer reaches the Hugging Face Hub.
- Module 0, "Coding agents in the terminal": an optional, self-serve hour on Day 1 from 08:00 to 09:00 (also usable as pre-work), with no notebook. `_variables.yml` gains `modules.m00` (with `notebook: false`), a `self_serve` schedule slot and `days.d1.self_serve`, and `agents_intro` (three.js and agent CLI npm versions, dated). The generators, tests, navbar, day, schedule, setup and teach pages, facilitator guide and pace sheet handle a module numbered 0.
- Site redesign: landing page with a hero, day cards and the module path; designed module headers; a module sidebar and previous/next links on lecture pages; a timetable with lecture, lab and break marked; a light/dark toggle. `scripts/gen_tables.py` now also writes `_includes/facts.md`, `path.md` and `sidebar.yml`.
- Lecture pedagogy pass (Modules 1–15): a recap box, check-yourself questions with folded answers, worked numeric examples and interactive Observable JS demos, all outside the 45-minute budget. The demos load Observable Plot from jsDelivr when the page is viewed.
- Lecture 14 (Agents), certification and harness pass: the agent harness defined and separated from evaluation and test harnesses; an ARC-AGI worked example of the same model in different harnesses, with cost per solved task; tool design, stopping and enforcement, escalation triggers and hand-offs; a new section 9 on workflow and agentic design patterns, coordinators and subagents, and context as a budget, with an optional Claude Agent SDK and MCP mapping. Drawn from Anthropic's *Claude Certified Architect – Foundations* exam guide and engineering posts, Andrew Ng's letters and ARC Prize's results. Module 0 names the harness; Module 15's further study points to Ng's course and the certification guide; `references.qmd` lists every new source. Lab 14's stretch section has four parts: the verify node, plus a research subagent with a coverage check, compaction that keeps the facts, and a stand-alone hand-off record, each with a folded solution and a scripted checkpoint.

### Changed

- **Title case** for titles and headings (APA rule, CONTRIBUTING.md): module and day titles, schedule slots, navigation, page, section, exercise, slide and callout headings. `scripts/titlecase.py` holds the rule. The References page now reads its module and day titles from `_variables.yml`.
- Workshop Lectures v1 is rebuilt from the October 8 pages (703,608 characters, 191,544 tokens); Labs 13 to 15 pin the new hash. The builder follows the move to `modules/`.
- The notebooks page gives one run order (harness, setup, data, exercises) and explains the three checkpoint messages. It no longer says Lab 9's files are unbuilt, and it names the one file that passes between labs: Lab 11's optional export for Lab 12. CONTRIBUTING.md lists all four generated notebook cells and gains capitalization, spelling and terminology rules. Published text says "labeled" and "center". Module 14 tells the lab's checkpoint cells apart from LangGraph's checkpoints.
- Each agenda says that a lab exercise using a Reference section restates what it needs. The three such sections (Modules 1, 3 and 9) open with a pointer to the exercise.
- Fixed: the masked row of `05-self-attention.svg` had lost its arrowheads, because its marker shared the id `d` with each figure's description. The marker is now `dm` in all twelve figures of `scripts/make_figures_05_08.py`.
- Workshop voice, in place of a course's: there are no lectures. `lectures/` is now `modules/`, and the block before each lab is a **briefing** (`schedule.clocks.*.shape`, the readiness fields, the timetable bars). Every module page opens the way a workshop module does: a details panel (duration, level on the 100-400 scale, lab runtime, accounts and cost, what runs without API keys), **What you will build**, **Before you start**, then **In the lab** - the notebook's own parts, exercises and minutes, read from its headings by `scripts/lab_steps.py` - and a **Challenge** block naming the stretch section. Section headings follow: Live plan is the Agenda (its anchor unchanged), Common misconceptions are Gotchas and troubleshooting, Readings are Further reading, and each "What Module N picks up" is Next steps. Morning retrieval practice is the **warm-up**, the closing synthesis is the **day wrap-up**, and `assessments.md` is `knowledge-checks.md`. The slots, their minutes and all content are unchanged. `_variables.yml` gains `levels` and a `level` per module; the landing strip counts the 79 hands-on exercises. Workshop Lectures v1 keeps its name, key and sha256: it is a frozen artifact built from one commit, not vocabulary.
- A social preview card for the repository, `images/social-preview.png` (1280x640), built from `_variables.yml` and the notebooks by `scripts/make_social_preview.py`.

- The lecture snapshot that Labs 13 to 15 retrieve from (Workshop Lectures v1) is rebuilt from the revised lectures: 684,704 characters, up from 544,974. It no longer carries each lecture's in-room timetable or the demos' code. Its status stays provisional.
- Lab 6's logits for Lab 11 are committed (`data/lab06_logits.npz`, `datasets.lab06_logits`): DistilBERT fine-tuned with Lab 6's GPU settings on the build Mac's GPU, not a T4. - Lab 9's preference data are built and committed (`data/lab09_prompts.json`, `data/lab09_preferences.jsonl.gz`, `data/lab09_reward_model.pt`), with `models.causal_lm_revision` pinned. The first build on real GPT-2 samples failed two of its own acceptance criteria (tie share 0.756, $\mathrm{Acc}^\star$ 0.596), because continuations of "... and said" rarely contain a list word. Every frame now ends just before a feeling ("... and felt so", "... feeling so"); the gold rule, the lengths and the Lab 9 → Lab 10 interface are unchanged. See "As built" in `briefs/09-preference-learning.md`.
- Lecture 10, Lab 10 and exit question 10.4 no longer say that the gold reward falls through the cap or the crowding term. They name the three ways the gold rule allows (no credit past three distinct positive words, crowding, and fewer positive or more negative words). - Dated environment and release gate (PLAN.md section 8, Phase 6). `uv.lock` is committed and CI runs on it (`--locked`); a weekly drift leg tries the newest allowed versions. `scripts/release_check.py` lists what stands between a commit and "ready to teach", and `.github/workflows/release.yml` creates a GitHub Release from a `v*` tag only when nothing does.

Day pages gain a generated run sheet, and lecture headers show when the lecture, lab and debrief run. `scripts/check_browser.py` checks the rendered site in Chromium at four desktop sizes in both themes, in CI too.
